## 目标

1. **列表定义更省事**：`quickplay_lists` 不再手写 `id`，改写成 `join:"加入命令"`（完整命令，如 `function repel/join`），id 按书写顺序自动分配（从 2 开始，1 保留给聊天栏列表）
2. **分类分组**：`category:"main"` 直接显示在主界面；其他分类在主界面显示 `【分类名】` 按钮，点开进入只含该分类游戏的内嵌子对话框（客户端本地切换，无 tick 延迟）
3. `quickjoin` 的 52 行硬编码表删掉，改成按 id 查 storage 并交给现成的 `cmd:run_cmd` 执行

## 机制

- **自动编号**：`quickplay_lists` 开头 `scoreboard players set quickplay.id temp 1`，每个条目 `add 1` → 第 1 个游戏 id=2；同一列表每遍跑出来的 id 一致
- **注册**：每个条目写入 `storage minecraft:quickplay joins."<id>" = {command:"<join>"}`；`/reload` 时由 setup 跑一遍 showmode 0，保证没开过对话框也能直接 `/trigger quickplay set <id>`
- **加入**：按钮执行 `/trigger quickplay set <id>` → `quickjoin` 用 `$(id)` 取 `joins."<id>"` → `function cmd:run_cmd with storage minecraft:quickplay joins."<id>"`（`cmd:run_cmd` 就是 `$$(command)`，utils 包里的现成宏）
- **分类**：两遍构建同一个列表——第一遍 `main` 条目进主对话框、其余按 `category` 收进 `storage minecraft:temp quickplay.cats."<分类名>"`；第二遍为每个新分类追加 `show_dialog` 按钮，内联子对话框的 `actions` 用 `set from` 灌入（内联写法本包 `dialog/menu.json:31` 已在用）

## 注意点

- **id 会变**：自动编号后与旧手写 id 不再一致（如击退游戏 33→3）。已确认 `quickplay` 分数只被 quickplay 相关文件使用，`globle.game` 是另一套游戏实例计数器，不受影响
- **依赖 `cmd:run_cmd`**：来自 `utils` 数据包（`utils/data/cmd/function/run_cmd.mcfunction`，内容就是 `$$(command)`），需确保该包在世界里启用
- **性能**：列表只在点击开对话框、`/reload` 时跑，不在 tick 里；一次约 52×2 次宏调用，几毫秒量级
- `joins."<id>"` 每遍构建重写相同值，幂等；`storage minecraft:quickplay` 与 scratch 用的 `storage minecraft:temp quickplay` 分开，构建时的清空不会影响注册表
